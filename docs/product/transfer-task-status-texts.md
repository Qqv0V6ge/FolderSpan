# 任务传输提示文本说明

本文汇总当前文件复制/移动任务在 UI 中展示的提示文本，便于后续统一文案、排查任务状态显示问题，以及给新链路复用相同文案。

说明：
- 当前文档已覆盖 `Local / Device / Share / Network` 相关任务链路里“主要的静态提示文本”和“进度模板”。
- 但它仍不是“所有最终展示字符串的绝对全集”，因为部分失败文案来自异常透传、远端返回消息或动态拼接文本。
- 如果后续要做完全穷举，应再补一份“动态错误来源表”（异常文案、HTTP 响应透传、远端进度消息）。
- 目录创建阶段现已优先把目标目录路径直接写入提示文本，便于从任务列表/详情里判断当前正在创建哪个文件夹。

## 展示原则
- 任务详情主要使用 `Task.result` 展示当前阶段文案，使用 `Task.values["path"]` 展示当前面向用户的目标路径。
- 跨端中转场景优先显示“最终目标路径”，不暴露 `sync-stage` 这类临时中转路径。
- 进度型文案统一使用“百分比 + 分块进度 + 速度 + 剩余时间”的格式。
- 目录扫描阶段的 result 文案只展示扫描状态和已发现数量；扫描速度、正计时、并行数展示在任务指标区，其中正计时复用“预计剩余”位置。

## 通用文案

### 取消与失败
- `任务已取消`
- `复制失败`
- `创建失败`
- `文件夹创建失败`
- `创建目标文件夹失败`
- `写入失败`
- `读取失败`
- `上传失败`
- `遍历源目录失败`
- `设备离线`

### 目录扫描/准备阶段
- `正在获取需要复制的数据`
- `正在获取需要复制的数据：已发现 {count} 项`
- 指标区：`速度 {itemsPerSecond} 项/s`、`预计剩余 {elapsed}`、`并行 {currentParallelism}`
- `正在创建文件夹：{path}`
- 当目标路径暂时不可用时，才回退为 `正在创建文件夹中...`

### 删除准备阶段
- `正在获取需要删除的数据`
- `正在获取需要删除的数据：已发现 {count} 项`
- 指标区：`速度 {itemsPerSecond} 项/s`、`预计剩余 {elapsed}`、`并行 {currentParallelism}`
- 某些删除流程会临时把待删除路径直接写入结果区，用于提示当前正在整理的删除项。

## 传输阶段文案模板

### 本地直写类
- 开始提示：
  - `开始传输`
- 进度提示：
  - `传输进度 {percent} ({doneBlocks}/{totalBlocks}), 速度 {speed}, 剩余 {eta}`

适用方向：
- `Local -> Local`
- 复用本地文件写入实现的 `Share/SystemShare -> Local` 场景
- 目录复制时单个本地文件的写入阶段

### 下载类
- 开始提示：
  - `开始下载`
- 进度提示：
  - `下载进度 {percent} ({doneBlocks}/{totalBlocks}), 速度 {speed}, 剩余 {eta}`

适用方向：
- `Network -> Local`
- `Share -> Local`
- `Device -> Local`
- 部分目录级批量下载场景

### 上传类
- 开始提示：
  - `开始上传`
- 进度提示：
  - `上传进度 {percent} ({doneBlocks}/{totalBlocks}), 速度 {speed}, 剩余 {eta}`

适用方向：
- `Local -> Network`
- `Local -> Device`
- 目录级批量上传场景

### 传输类
- 开始提示：
  - `开始传输`
- 进度提示：
  - `传输进度 {percent} ({doneBlocks}/{totalBlocks}), 速度 {speed}, 剩余 {eta}`

适用方向：
- `Device -> Device`
- `Network -> Device` 单文件直通中继
- `Device -> Network` 单文件中转第一阶段（设备到本地临时文件）

## 设备内复制控制文案
- `正在设备内复制`
- `正在请求远端暂停`
- `暂停请求已发送，等待远端就绪`
- `正在请求远端继续`
- `已恢复，等待继续复制`

这些文案用于同设备内远端复制任务的控制链路，不参与 `上传进度` / `下载进度` / `传输进度` 模板。

### 设备内复制控制失败回退
- `远端暂停请求失败`
- `远端继续请求失败`

这两条通常只在控制请求本身失败、且没有更具体远端错误文案可展示时作为兜底文本出现。

## 跨端中转链路的用户可见阶段

### `Network -> Device`
- 单文件优先显示：
  - `开始传输`
  - `传输进度 ...`
- 若协议或目录场景回退到本地中转，则后续可能继续出现设备侧既有文案（例如 `开始上传` / `上传进度 ...`），但路径仍应保持为最终目标路径。

### `Device -> Network`
- 单文件当前显示两段用户可见阶段：
  1. 设备读取到本地临时文件：
     - `开始传输`
     - `传输进度 ...`
  2. 本地临时文件上传到网络端：
     - `开始上传`
     - `上传进度 ...`
- 两段均应显示最终网络目标路径，不显示临时文件路径。

## 按来源模块补充

这一节按统一的三阶段描述每个来源模块：
- 获取数据
- 创建文件夹
- 传输文件

说明：
- 三阶段是统一抽象，不代表每条链路都会显式展示所有阶段。
- 单文件场景通常不会单独展示“创建文件夹”。
- 错误文案允许各来源模块不同，但阶段结构尽量保持一致。

### Local

#### 获取数据
- 目录复制前通常显示：
  - `正在获取需要复制的数据`
  - 并行遍历中会节流更新为 `正在获取需要复制的数据：已发现 {count} 项`
  - 扫描速度、正计时、并行数显示在任务指标区，不再拼入 result 文案。
- 删除准备阶段显示：
  - `正在获取需要删除的数据`
  - 并行遍历中会节流更新为 `正在获取需要删除的数据：已发现 {count} 项`
  - 扫描速度、正计时、并行数显示在任务指标区，不再拼入 result 文案。

#### 创建文件夹
- 目录复制时通常显示：
  - `正在创建文件夹：{path}`

#### 传输文件
- `Local -> Local`
  - `开始传输`
  - `传输进度 ...`
- `Local -> Device`
  - `开始上传`
  - `上传进度 ...`
- `Local -> Network`
  - `开始上传`
  - `上传进度 ...`

#### 常见错误
- 本地直写类错误更常见的是：
  - `写入失败`
  - 直接透传异常消息

### Device

#### 获取数据
- 设备目录复制通常不额外显示独立“获取数据”提示，更多是在设备侧遍历完成后直接进入传输。
- `Device -> Device` 的设备内复制控制链路会显示：
  - `正在设备内复制`
- JS / wasmJs 浏览器通过 WebRTC 下载设备目录或多选文件并打包为 ZIP 时，会先显示：
  - `正在扫描文件夹` 或 `正在扫描文件`
  - 并行遍历中会节流更新为 `正在获取需要复制的数据：已发现 {count} 项`
  - 扫描速度、正计时、并行数显示在任务指标区，不再拼入 result 文案。

#### 创建文件夹
- 设备目录复制若需要目标端预创建目录，当前会沿用统一的动态路径提示：
  - `正在创建文件夹：{path}`

#### 传输文件
- `Device -> Local`
  - `开始下载`
  - `下载进度 ...`
- `Device -> Device`
  - `开始传输`
  - `传输进度 ...`
- `Device -> Network`
  - 第一阶段：`开始传输` / `传输进度 ...`
  - 第二阶段：`开始上传` / `上传进度 ...`
- JS / wasmJs 浏览器 WebRTC ZIP 下载
  - 单个文件写入 ZIP 时先显示 `正在打包 {relativePath}`
  - 随后复用传输模板：`传输进度 {percent} ({doneBlocks}/{totalBlocks}), 速度 {speed}, 剩余 {eta}`
  - 所有文件写入 ZIP 后，浏览器 ZIP Worker 只提供完成/失败事件，不提供可靠百分比进度，因此收尾阶段显示固定文本：`正在完成 ZIP 打包`
  - ZIP 写入当前为串行文件流，传输阶段指标区并发显示为 `1`，结束后回到 `0`。

#### 常见错误
- `设备离线`
- `读取失败`
- `写入失败`
- 远端控制失败时可能显示：
  - `远端暂停请求失败`
  - `远端继续请求失败`

### Share

#### 获取数据
- `Share -> Local` 通常显示：
  - `正在获取需要复制的数据`

#### 创建文件夹
- 目录级 Share 复制通常显示：
  - `正在创建文件夹：{path}`

#### 传输文件
- 文件下载阶段：
  - `开始下载`
  - `下载进度 ...`
- `SystemShare -> Local` 若落到本地直写链路，则通常显示：
    - `开始传输`
    - `传输进度 ...`

#### 常见错误
- `复制失败`
- `文件夹创建失败`
- `创建失败`
- `读取失败`
- `写入失败`

### Network

#### 获取数据
- 目录级网络复制前通常会先遍历远端或本地目录树。
- 当前典型相关文案包括：
  - `正在获取需要复制的数据`
  - `遍历源目录失败`

#### 创建文件夹
- 目录级网络复制通常会先创建目标目录，相关文案/错误包括：
  - `正在创建文件夹：{path}`
  - 路径缺失时回退：`正在创建文件夹中...`
  - `创建目标文件夹失败`
  - `文件夹创建失败`

#### 传输文件
- `Network -> Local`
  - `开始下载`
  - `下载进度 ...`
- `Network -> Device`
  - 单文件直通：`开始传输` / `传输进度 ...`
  - 回退中转：后续可能显示 `开始上传` / `上传进度 ...`
- `Local -> Network`
  - `开始上传`
  - `上传进度 ...`

#### 常见错误
- `上传失败`
- `读取失败`
- `写入失败`
- 以及网络协议返回的动态错误文本

## 占位符说明
- `{count}`：扫描阶段已发现的文件/目录项数量
- `{itemsPerSecond}`：扫描阶段发现条目的平均速度，例如 `24.4`
- `{currentParallelism}`：扫描阶段当前遍历并行数
- `{elapsed}`：扫描阶段正计时，例如 `00:12`；进入具体复制/删除执行阶段后重置为 `00:00`
- `{percent}`：已完成字节占总字节百分比，例如 `12.4%`
- `{doneBlocks}` / `{totalBlocks}`：按 `MAX_LENGTH` 分块后的完成块数与总块数
- `{speed}`：瞬时/平均速度，例如 `8.3 MB/s`
- `{eta}`：预计剩余时间，例如 `04:12`
