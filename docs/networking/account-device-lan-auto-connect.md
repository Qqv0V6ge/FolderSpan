# 同账号设备局域网自动连接

## 用户行为

文件共享设置中的“自动连接我的设备”默认关闭，并且只保存在当前设备。用户登录并开启后，客户端在常规局域网扫描中发现属于同一账号的设备时自动连接；对方发来的有效同账号设备连接请求也会自动同意。

该功能不要求用户配置访问密钥、身份密钥或角色。现有文件共享访问保护、手动连接、手动审批、永久拒绝和 TLS 证书校验保持独立生效。

## 信任来源

客户端通过账号设备列表的无缓存刷新路径获取短期可信快照，有效期为 5 分钟。设置开启、登录或账号切换时立即刷新，应用回到前台及局域网扫描需要信任时按需刷新。退出登录、切换账号、关闭设置及账号鉴权失败时立即清空快照。

账号设备条目只有同时提供以下 snake_case 可验证身份字段时才能进入自动信任集合；缺失字段的设备只保留普通人工流程：

- `device_key`
- `identity_public_key`
- `identity_algorithm`，当前支持 `SHA256withRSA`
- `identity_key_id`

客户端只接受上述正式字段，不解析 camelCase、嵌套 `identity` 或其它开发阶段旧格式。后端实现和接口变更不属于本仓库。

## 局域网证明

局域网 ping 请求携带随机 challenge。响应设备使用应用自动管理的设备私钥，对双方设备标识、`/ping`、challenge、时间和响应摘要签名。扫描方只有在账号成员资格、快照新鲜度和签名全部通过后才自动连接。

直接连接请求必须显式声明 `STANDARD` 或 `ACCOUNT_DEVICE` 授权模式。`ACCOUNT_DEVICE` 请求必须携带独立的 `lan-connect` 证明，绑定双方设备、`/api/devices/connect`、时间、nonce 和请求摘要；接收方执行时间窗校验与有界 nonce 防重放校验，缺少或无效证明时直接拒绝该账号授权请求，不降级到人工审批。`STANDARD` 请求继续使用普通手动或永久策略。发现证明与连接证明用途隔离，不能相互复用。

连接响应必须明确返回本次授权是否来自账号设备信任。当前客户端间协议不提供开发阶段旧字段或缺字段兼容；身份材料缺失的设备仍可作为普通设备发现并由当前协议手动连接，但不能仅凭 `deviceKey` 自动连接或自动同意。远程 WebRTC 不使用这套账号自动信任。

## 授权与撤销

入站连接的决策优先级为：永久拒绝、身份冲突或重放、有效同账号证明自动同意、现有人工/永久策略。自动同意优先复用设备已有角色，否则使用内置最小权限角色。

仅依赖本次账号会话建立的临时授权会被单独标记。当设备从刷新后的账号列表移除、用户退出登录或关闭设置时，客户端撤销这些临时授权并断开相应连接，不影响用户通过其它永久策略建立的授权。
