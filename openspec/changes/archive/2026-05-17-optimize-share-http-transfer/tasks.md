## 1. Implementation
- [x] 1.1 为共享路由新增流式文件输出端点，并复用现有鉴权与路径校验。
- [x] 1.2 将共享复制主链路改为高速 `/read-bytes` 并发直读，并限制单块 `4MB~8MB`、全局 `16` 并发和 `64MB` in-flight 内存预算。
- [x] 1.3 恢复传输状态头解析和 backoff，使 range 并发可随服务端压力自适应。
- [x] 1.4 收紧目录复制的文件级并发，并通过全局传输信号量避免并发放大。
- [x] 1.5 将 JVM/Android 本地范围读写改为 `FileChannel` 定点 IO。
- [x] 1.6 将任务进度和日志更新节流，避免每个数据块刷新任务状态。
- [x] 1.7 将 `/read-bytes` 提升为默认大文件复制端点，并保留 `/stream-file` 作为低内存兼容路径。
- [x] 1.8 为服务端共享路径解析增加短 TTL 缓存，并移除字节传输成功 debug 热日志。
- [x] 1.9 让匿名复制读取绕过请求 registry 自动注册。
- [x] 1.10 运行 OpenSpec 校验与目标编译验证。
- [x] 1.11 稳定大文件吞吐：并发 `/read-bytes` 改为按 offset 直接写出，并优化 Android `content://` 源端 range chunks 连续读取。
- [x] 1.12 提升稳定吞吐：将默认大文件复制管线收敛为 4MB~8MB 自适应分片 + 有界 worker 队列，避免额外流式重排层。
