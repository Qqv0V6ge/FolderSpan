## Purpose

定义用户主动粘贴独立 HTTP/HTTPS 地址时，系统如何在用户确认本次下载设置后创建可见任务，由任务安全检查、重试、按能力并行下载并把完整文件交付到分享列表，同时对失败和平台限制提供一致反馈。

## ADDED Requirements

### Requirement: 仅主动粘贴触发 URL 下载
系统 SHALL 仅在用户主动执行受支持的剪贴板粘贴操作后读取文本并考虑 URL 下载，且仅在用户确认由该次粘贴产生的下载设置弹窗后发起请求。

#### Scenario: 用户主动粘贴独立 URL
- **WHEN** 用户在非编辑态文件浏览上下文主动粘贴
- **AND** 剪贴板文本只有一条非空 HTTP/HTTPS URL
- **THEN** 系统显示该 URL 的下载设置弹窗
- **AND** 系统在用户确认前不发起网络请求

#### Scenario: 剪贴板变化不触发下载
- **WHEN** 剪贴板内容发生变化，但用户没有执行受支持的粘贴操作
- **THEN** 系统不读取该内容
- **AND** 系统不发起网络请求

#### Scenario: 生命周期事件不触发下载
- **WHEN** 应用启动、恢复前台或收到其他应用分享的纯文字
- **AND** 用户没有在 FolderSpan 内主动粘贴
- **THEN** 系统不因该事件发起 URL 下载
- **AND** 系统不显示粘贴 URL 设置或原文弹窗

#### Scenario: 编辑控件保留普通粘贴
- **WHEN** 用户在文本输入、文件编辑器或其他可编辑控件内粘贴 HTTP/HTTPS 文本
- **THEN** 控件执行平台默认的文字粘贴
- **AND** 系统不启动文件下载

### Requirement: 下载前弹窗确认本次请求设置
系统 SHALL 为独立 URL 显示下载设置弹窗，并 SHALL 在弹窗中提供重试次数、Cookie、User-Agent、自动请求头和线程数设置以及“下载”和“取消”操作；所有设置 SHALL 仅作用于本次任务。

#### Scenario: 原生平台显示全部设置
- **WHEN** Android、iOS 或 Desktop 识别到独立 HTTP/HTTPS URL
- **THEN** 弹窗显示可调整的重试次数、Cookie、User-Agent、自动请求头和线程数
- **AND** 重试次数与线程数具有明确的安全范围和默认值

#### Scenario: Web 显示浏览器限制
- **WHEN** Web 识别到独立 HTTP/HTTPS URL
- **THEN** 弹窗说明 Cookie、User-Agent 和浏览器禁止修改的请求头不可由应用覆盖
- **AND** 系统禁用这些不可用设置而不是暗示它们会生效

#### Scenario: 用户确认下载
- **WHEN** 用户检查或修改设置后选择“下载”
- **THEN** 系统先以本次设置创建一个可见下载任务
- **AND** 该任务开始执行后才访问 URL、检查响应并下载文件
- **AND** 设置值不成为下一次粘贴的隐式配置

#### Scenario: 用户取消设置弹窗
- **WHEN** 用户选择“取消”或关闭下载设置弹窗
- **THEN** 系统不发起网络请求
- **AND** 系统保留原始 URL 供后续再次粘贴或复制

#### Scenario: 设置值不合法
- **WHEN** 重试次数、线程数、Cookie 或 User-Agent 超出范围或包含不允许的控制字符
- **THEN** 系统阻止开始下载
- **AND** 弹窗指出需要修正的字段

### Requirement: URL 候选必须明确且独立
系统 SHALL 仅接受具有 HTTP 或 HTTPS scheme、有效主机且不包含用户信息的单条独立 URL；系统 MUST NOT 自动访问嵌入普通文字、与其他内容混合或一次包含多条的 URL。

#### Scenario: 独立 HTTPS URL 可检测
- **WHEN** 主动粘贴内容规范化后是一条具有有效主机的 HTTPS URL
- **THEN** 系统将其作为下载候选

#### Scenario: 独立 HTTP URL 可检测
- **WHEN** 主动粘贴内容规范化后是一条具有有效主机的 HTTP URL
- **THEN** 系统将其作为下载候选
- **AND** 后续请求仍须遵守当前平台的明文传输策略

#### Scenario: 混合或多条内容不访问网络
- **WHEN** 主动粘贴内容包含多条 URL、URL 与说明文字混合或 URL 内含用户信息
- **THEN** 系统不发起网络请求
- **AND** 系统把完整原文交给内容回退流程

#### Scenario: 其他 scheme 不访问网络
- **WHEN** 主动粘贴文本使用 `file`、`data`、`ftp` 或其他非 HTTP/HTTPS scheme
- **THEN** 系统不把它作为 URL 下载候选

### Requirement: 可下载响应具有明确判定
系统 SHALL 只把成功且总大小明确的最终 HTTP 响应认定为可下载文件；最终响应必须为 `2xx`，必须能从有效 `Content-Length` 或 `Content-Range` 确认文件总大小，并且具有附件声明、非 HTML 内容类型，或在缺少内容类型时具有可用的最终 URL 文件名。

#### Scenario: 附件响应可下载
- **WHEN** 最终响应为 `2xx`
- **AND** `Content-Disposition` 声明附件
- **THEN** 系统接受该响应为可下载文件

#### Scenario: 非 HTML 内容可下载
- **WHEN** 最终响应为 `2xx`
- **AND** 内容类型不是 `text/html` 或 `application/xhtml+xml`
- **THEN** 系统接受该响应为可下载文件

#### Scenario: 无法确认文件总大小
- **WHEN** 完整响应未提供有效 `Content-Length`
- **AND** Range 探测也未提供具有已知总长度的有效 `Content-Range`
- **THEN** 系统不读取或发布该响应体为文件
- **AND** 系统清理本次临时资源并进入内容回退流程

#### Scenario: 普通网页不作为文件下载
- **WHEN** 最终响应为内联 HTML 网页且未声明附件
- **THEN** 系统不发布下载文件
- **AND** 系统把原始粘贴内容交给内容回退流程

#### Scenario: 失败状态不发布文件
- **WHEN** 最终响应不是 `2xx`，或网络请求、TLS 校验、重定向或响应读取失败
- **THEN** 系统不发布部分文件
- **AND** 系统显示可诊断的失败反馈并保留原始内容供用户复制

### Requirement: URL 检查与下载由现有任务系统承载
系统 MUST 在用户确认后先向现有 `TaskState` 注册下载任务，再由该任务在不阻塞用户界面的后台执行 URL 访问、响应检查、网络读取与文件写入；任务系统 SHALL 提供检查中、下载中、重试等待、进度、失败、成功和取消状态，确认后的进行中状态 MUST NOT 再由独立下载弹窗重复显示。

#### Scenario: 确认前没有任务或请求
- **WHEN** 独立 URL 的下载设置弹窗仍在显示
- **AND** 用户尚未选择“下载”
- **THEN** 任务列表不新增 URL 下载任务
- **AND** 系统不访问该 URL

#### Scenario: 确认后先创建任务再检查
- **WHEN** 用户在下载设置弹窗选择“下载”
- **THEN** 任务列表先出现 URL 下载任务
- **AND** 任务状态显示正在检查目标
- **AND** URL 请求由该任务的执行处理器发起

#### Scenario: 下载期间界面保持响应
- **WHEN** URL 下载正在进行
- **THEN** 用户界面保持可交互
- **AND** 任务列表显示已接收字节、总字节、速度、当前尝试和可获得的下载进度
- **AND** 系统不显示独立的下载进度弹窗

#### Scenario: 用户取消下载
- **WHEN** 用户从任务界面取消正在检查或下载的 URL 任务
- **THEN** 系统停止继续读取响应和写入文件
- **AND** 系统删除本次下载的未完成资源

#### Scenario: 下载对象设置通用任务数据
- **WHEN** 下载协调器收到包含已接收字节和有效总大小的下载进度对象
- **THEN** 系统按字节比例设置 Task 的 `progressCur`（0–100）及 `progressMax=100`，由原通用任务弹窗显示进度
- **AND** 既有结果消息包含已下载大小、总大小、百分比及尝试状态，速度、预计剩余时间和并发数继续通过原运行时指标展示
- **AND** 不修改原 Task 弹窗布局或增加下载专用分支，超过 2 GB 的字节数保持正确，进度变化及时更新任务对象

#### Scenario: 下载进度对象尚未包含总大小
- **WHEN** 下载协调器收到尚未包含有效总大小的下载进度对象
- **THEN** 任务结果消息显示已有的接收字节数及“总大小未知”
- **AND** 系统设置 `progressCur=0`、`progressMax=100`，消息不生成百分比，不能把未知大小显示为已完成

#### Scenario: 已有下载时再次粘贴
- **WHEN** 一个粘贴 URL 下载仍在进行
- **AND** 用户再次触发 URL 粘贴下载
- **THEN** 系统不并发创建第二个下载
- **AND** 系统向用户说明已有下载正在进行

### Requirement: 下载成功结果交付文件浏览列表或粘贴目标
系统 SHALL 在 URL 任务成功发布完整暂存文件后，将直接粘贴 URL 的下载结果注册到侧栏系统分享来源并在主文件浏览器中显示；从已打开 URL 文件条目发起的复制粘贴 SHALL 在同一下载任务内将完整文件写入用户选定的目标。两条路径均 SHALL NOT 打开发送文件用的 `FileShareScreen`。

#### Scenario: URL 检查和下载成功
- **WHEN** 下载任务确认最终响应可下载并完整发布文件
- **THEN** 系统把该文件加入侧栏系统分享来源
- **AND** 系统在主文件浏览器中显示该来源的文件列表
- **AND** 文件交付成功后移除下载 Task 及其持久快照，不保留已完成任务

#### Scenario: 已打开 URL 文件粘贴到选定目录
- **WHEN** 用户选择 URL 文件条目并粘贴到可写目录，随后确认下载设置
- **THEN** 系统使用已有文件冲突规划决定替换、跳过或保留两者
- **AND** 同一下载任务完成网络读取与目标文件交付
- **AND** 目标文件交付成功后移除下载 Task，不在复制尚未完成时提前移除
- **AND** 交付结束或取消后释放本次 staging

#### Scenario: 下载完成但目标交付失败
- **WHEN** 完整暂存文件已下载，但加入系统分享来源或复制到目标失败
- **THEN** 系统保留失败 Task 供用户查看原因
- **AND** 释放未交付的暂存资源

#### Scenario: URL 检查或下载失败
- **WHEN** 任务无法确认可下载响应或下载未成功发布完整文件
- **THEN** 系统不改变分享列表
- **AND** 任务状态更新为失败
- **AND** 因本次操作来自主动粘贴，系统可显示脱敏失败原因和可复制原始 URL

#### Scenario: 暂存资源随分享引用释放
- **WHEN** 直接粘贴 URL 产生的下载文件仍位于系统分享来源
- **THEN** 系统保持暂存文件可读
- **AND** 系统分享来源关闭或应用退出后释放对应暂存资源

### Requirement: 下载支持有界重试与可回退的线程数
系统 SHALL 按用户为本次任务选择的重试次数处理可恢复失败，并 SHALL 在服务器支持稳定字节范围时按选择的线程数分段下载；系统 MUST NOT 因重试或并行分段发布重复、不完整或不同版本拼接的文件。

#### Scenario: 可恢复失败触发重试
- **WHEN** 请求遇到传输中断、读取超时、HTTP `408`、`429` 或 `5xx`
- **AND** 本次任务仍有剩余重试次数
- **THEN** 系统使用有上限的退避延迟重试失败的请求或分段
- **AND** 总尝试次数与界面状态可诊断

#### Scenario: 不可恢复失败不重试
- **WHEN** 请求遇到证书校验失败、用户取消、设置错误、`401`、`403`、其他不可恢复的 `4xx` 或明确的 HTML 响应
- **THEN** 系统不消耗剩余次数进行自动重试

#### Scenario: 服务器支持安全分段
- **WHEN** 用户选择多于一个线程
- **AND** 服务器以有效 `206`、一致的总长度和稳定校验标识支持字节范围
- **THEN** 系统把文件划分为不重叠分段并在后台并行下载
- **AND** 发布前验证每段范围、总长度和响应版本一致

#### Scenario: 服务器不支持安全分段
- **WHEN** 用户选择多于一个线程但服务器忽略 Range、缺少稳定校验标识或返回不一致分段
- **THEN** 系统自动回退为单线程完整下载
- **AND** 系统清理探测请求或分段产生的临时内容

### Requirement: 下载请求只使用本次确认的身份与凭据
原生平台的下载请求 SHALL 默认使用不含用户或设备身份的 FolderSpan `User-Agent`，并 MAY 使用用户在本次设置弹窗明确输入的 User-Agent 与 Cookie；系统 MUST NOT 读取、复用或持久化其他应用会话凭据，Web 平台 SHALL 使用浏览器管理的 User-Agent 并以不携带凭据的方式请求。

#### Scenario: 原生请求发送最小 User-Agent
- **WHEN** Android、iOS 或 Desktop 发起粘贴 URL 下载
- **AND** 用户没有覆盖本次 User-Agent
- **THEN** 请求使用 `FolderSpan/<应用版本> (<平台>) ClipboardUrlDownload/1` 格式的 `User-Agent`
- **AND** 该值不包含用户 ID、设备 ID、设备名称或网络地址

#### Scenario: 原生请求使用本次自定义 User-Agent
- **WHEN** 用户在原生平台为本次任务输入合法的 User-Agent
- **THEN** 本次请求和允许的重定向使用该 User-Agent
- **AND** 系统不持久化或记录该值

#### Scenario: Web 使用浏览器 User-Agent
- **WHEN** Web 发起粘贴 URL 下载
- **THEN** 系统不尝试覆盖浏览器控制的 `User-Agent`

#### Scenario: 原生请求使用本次 Cookie
- **WHEN** 用户在原生平台为本次任务输入合法的 Cookie
- **THEN** 系统只向与初始 URL 同源的请求发送该 Cookie
- **AND** 跨源重定向不携带该 Cookie
- **AND** 系统不持久化或记录 Cookie

#### Scenario: 不借用现有凭据
- **WHEN** 任一平台发起或重定向粘贴 URL 下载请求
- **THEN** 请求不携带应用保存的 Cookie 或 Authorization
- **AND** 响应的 `Set-Cookie` 不被持久化供后续请求使用
- **AND** Web 请求使用 `credentials: omit`

#### Scenario: 用户未提供所需凭据
- **WHEN** 下载地址依赖 Cookie 或 Authorization 才能返回文件
- **AND** 本次请求没有用户明确提供且平台允许的 Cookie
- **THEN** 系统不借用现有应用会话绕过认证
- **AND** 下载失败后进入内容回退流程

### Requirement: 自动请求头保持最小且可解释
原生平台 SHALL 提供“自动请求头”设置；启用时系统只生成下载所需的非敏感标准请求头，禁用时仍可发送协议栈强制头和实现已选线程所必需的 Range 校验头。系统 MUST NOT 自动注入 Authorization、Cookie、Referer 或可识别用户/设备的头。

#### Scenario: 启用自动请求头
- **WHEN** 用户启用“自动请求头”并确认下载
- **THEN** 原生请求自动添加稳定的 `Accept` 和字节一致性所需头
- **AND** `Accept-Encoding` 使用与长度及分段校验兼容的值

#### Scenario: 禁用自动请求头
- **WHEN** 用户禁用“自动请求头”并确认下载
- **THEN** 系统不添加可选的应用级标准请求头
- **AND** 系统仍保留 HTTP 栈强制头与安全下载所必需的 Range、If-Range 或长度校验行为

#### Scenario: 自动头不包含敏感凭据
- **WHEN** 系统构造任一初始、重试、重定向或分段请求
- **THEN** 自动请求头不包含 Authorization、Cookie、Referer、用户标识或设备标识
- **AND** Cookie 只能来自本次弹窗的独立 Cookie 字段

### Requirement: 流式下载受已知长度和重定向边界约束
系统 MUST 只在确认文件总大小后流式写入受控临时资源，限制重定向次数，持续核对已接收字节与已声明总长度，清理失败的部分内容，并从可信响应元数据生成安全文件名；系统 MUST NOT 设置应用级固定文件大小上限。

#### Scenario: 已知总大小不受固定上限拒绝
- **WHEN** 响应提供有效的文件总大小
- **THEN** 系统不因该大小超过原生或 Web 的固定应用阈值而拒绝下载
- **AND** 下载仍受平台实际存储能力、超时、取消和长度一致性校验约束

#### Scenario: 实际字节与已知总大小不一致
- **WHEN** 下载接收的实际字节数少于或超过已确认的文件总大小
- **THEN** 系统不发布该文件
- **AND** 系统删除部分文件或片段

#### Scenario: 重定向受限
- **WHEN** 下载发生重定向
- **THEN** 原生平台最多跟随五次重定向，Web 使用浏览器受限的重定向处理
- **AND** 每个目标仍必须使用 HTTP 或 HTTPS

#### Scenario: 安全解析文件名
- **WHEN** 下载响应可发布为文件
- **THEN** 系统依次尝试使用 `filename*`、`filename`、最终 URL 路径和内容类型推断名称
- **AND** 系统移除路径分隔符、控制字符及其他不安全名称成分
- **AND** 无可用名称时使用带时间戳的下载文件名

### Requirement: 平台网络策略不可被下载器绕过
系统 MUST 遵守平台 TLS、ATS、CORS、混合内容和明文流量策略，不得为了粘贴 URL 下载全局降低平台安全配置。

#### Scenario: iOS 阻止不允许的 HTTP 请求
- **WHEN** iOS ATS 不允许目标 HTTP 地址
- **THEN** 系统不放宽全局 ATS 配置
- **AND** 系统进入内容回退流程

#### Scenario: Web 请求被 CORS 或混合内容策略阻止
- **WHEN** 浏览器因 CORS 或混合内容策略不允许读取目标响应
- **THEN** 系统不尝试绕过浏览器策略
- **AND** 系统进入内容回退流程

#### Scenario: TLS 校验失败
- **WHEN** HTTPS 目标无法通过系统信任校验
- **THEN** 系统不接受不受信任证书
- **AND** 系统不发布下载文件
