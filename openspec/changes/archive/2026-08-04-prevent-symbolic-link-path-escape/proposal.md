## Why

目录统计、删除、链接分享和设备路径权限目前会把符号链接当作普通目录处理，可能越过用户选择或授权的根目录，造成大小统计虚高、无限递归、内存溢出、越权读取或误删链接目标。该问题已在真实项目目录中触发，且删除与远程分享链路具有数据破坏和权限绕过风险，需要统一修复而不是继续在单个界面打补丁。

## What Changes

- 为跨平台文件元数据增加可序列化、向后兼容的符号链接标识，使本地、设备、分享和网络遍历能够统一识别链接。
- 所有目录统计、复制、移动、删除、拖拽导入、归档与遗留遍历入口默认不跟随符号链接，并使用有界状态避免循环和全量条目常驻内存。
- 将本地和 Android 特权目录删除改为不跟随链接的安全删除；删除符号链接时只删除链接本身，绝不递归进入目标。
- 链接分享在浏览、下载、批量下载和上传前验证解析后的目标仍位于获授权共享根内，并拒绝经过符号链接逃逸的路径。
- HTTP 与 WebRTC 设备路径 RPC 在权限判断和实际文件访问之间保持同一解析边界，拒绝通过授权根内符号链接访问根外路径。
- 为本地、Android 特权、设备 RPC、链接分享和递归遍历补充符号链接、祖先循环、根外目标、删除安全与低内存回归测试。

## Capabilities

### New Capabilities

- `symbolic-link-safety`: 定义跨平台符号链接元数据、默认不跟随策略、安全删除、真实路径根边界和有界递归行为。

### Modified Capabilities

- `manage-file-operation-tasks`: 复制、移动、删除和属性统计的目录清单不得通过符号链接离开源根，删除不得进入链接目标。
- `browse-share-network`: 链接分享的浏览、下载、批量下载和上传必须保持在授权共享根的真实路径边界内。
- `webrtc-device-path-rpc`: HTTP 与 WebRTC 设备路径操作必须在解析符号链接后执行同一角色路径权限约束。
- `android-root-file-access`: Root 和 Shizuku 特权文件操作必须提供与普通本地 IO 一致的不跟随遍历和安全删除语义。

## Impact

- 影响 `FileSimpleInfo` 及其 HTTP/WebRTC/数据库或映射序列化边界，新增字段必须提供默认值以兼容旧端。
- 影响 `PathUtils`、Android 特权文件服务、统一目录收集器、文件任务执行器、Android 拖拽处理、链接分享路由和设备权限校验。
- 网络协议若无法可靠识别符号链接，将采用保守策略：不把链接当作可递归目录，或由协议适配器显式声明能力。
- 不新增外部依赖；现有客户端 JSON/RPC 字段保持兼容，旧端缺失链接标识时按非链接处理，但服务端边界校验仍作为最终保护。
