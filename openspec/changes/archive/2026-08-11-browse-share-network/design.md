## Context

链接分享浏览器页面由 `IndexTemplate.renderFileGrid` 根据 `FileSimpleInfo` 生成目录和文件卡片，条目模型已经提供 `isHidden`，共享样式表负责卡片的整体外观。当前渲染没有把该字段映射为视觉状态，因此在允许显示隐藏数据的会话中，两类条目看起来完全相同。

## Goals / Non-Goals

**Goals:**

- 让隐藏文件和隐藏目录均具有稳定、统一且可测试的低透明度样式。
- 保持非隐藏条目的现有视觉表现。
- 保持卡片现有 DOM 结构、链接目标、下载、预览和键盘焦点行为。

**Non-Goals:**

- 不改变隐藏数据的识别、过滤或授权规则。
- 不新增隐藏状态文字、图标或设置项。
- 不修改链接分享 API 响应或 `FileSimpleInfo` 数据模型。

## Decisions

### 在卡片根节点添加隐藏状态修饰类

目录和文件卡片的根节点根据 `FileSimpleInfo.isHidden` 条件性添加 `file-card--hidden`。修饰类位于根节点可以覆盖图标、名称、元信息和操作区域，并避免在两个卡片分支中分别修改每个子元素。

备选方案是为各子元素分别添加透明度，但容易遗漏预览、下载等操作图标，也会增加后续维护成本。

### 使用 CSS `opacity` 统一降低透明度

`file-card--hidden` 使用固定的 `opacity: 0.56`，非隐藏卡片不添加该类并沿用浏览器默认的 `opacity: 1`。透明度施加在根节点，符合“完整条目统一区分”的规格，同时不改变布局与点击区域。由于现有 `md3FadeUp` 动画的终态透明度为 `1`，隐藏卡片使用相同位移和时长的 `md3FadeUpHidden` 动画，并把终态透明度保持为 `0.56`。

备选方案是分别混合文本和背景颜色，但需要为浅色、深色主题维护多组颜色，且不能天然覆盖所有子元素。

### 通过模板输出测试固定状态映射

模板测试同时渲染隐藏与非隐藏的文件、目录，验证只有 `isHidden=true` 的根卡片具有修饰类，并继续断言原有链接属性存在。样式表保持单一、明确的透明度声明。

## Risks / Trade-offs

- [较低透明度可能被误解为禁用] → 保留完整点击、焦点和悬停行为，不使用 `disabled`、`aria-disabled` 或 `pointer-events`。
- [整卡透明度会降低操作图标对比度] → 使用高于禁用态的 `0.56`，在区分度与可读性之间保持平衡。
- [仅靠透明度不是完整的无障碍状态说明] → 本变更只实现用户要求的视觉区分；若后续需要面向辅助技术暴露隐藏状态，应另行设计可本地化标签。

## Migration Plan

无需数据迁移。部署模板与静态样式后立即生效；回滚时移除修饰类映射与对应 CSS 即可。
