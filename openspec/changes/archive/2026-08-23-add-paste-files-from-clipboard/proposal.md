## Why

应用当前能够读取剪贴板中的路径并打开其所在位置，却不能像系统文件管理器一样把剪贴板中的真实文件粘贴到当前目录。现有跨平台文件拖拽已经解决了本地路径、内容 URI、临时文件和浏览器文件对象的接入问题，因此可以在保持平台权限与资源生命周期安全的前提下扩展为剪贴板文件粘贴。

## What Changes

- 增加平台适配的“粘贴剪贴板文件”入口，支持一次粘贴一个或多个真实文件载荷，以及浏览器、图片查看器和截图工具提供的图片内容。
- 当剪贴板只有图片位图或 `image/*` 二进制表示而没有文件身份时，将其准备为应用持有的图片文件；优先保留平台提供的编码格式，否则无损编码为 PNG。
- 将剪贴板文件复制到当前可写目录，并遵循当前磁盘的粘贴权限、现有冲突选择和文件任务语义。
- 在 Desktop 和 Web 的文件浏览上下文支持 `Ctrl/Cmd+V`，且不拦截文本输入和文件编辑器中的普通文本粘贴；移动端提供可发现的显式操作入口。
- 复用文件拖拽的数据提取、URI 注册、临时文件暂存及浏览器内存文件接入逻辑，并在任务完成、取消或失败后释放临时资源。
- 保留现有“从剪贴板打开”能力；普通文本路径和 URL 不会被新能力隐式复制。
- 对不受支持、不可读取或部分读取失败的剪贴板条目提供明确反馈，并允许其余有效文件继续粘贴。

## Capabilities

### New Capabilities

- `paste-clipboard-files`: 定义跨平台读取真实剪贴板文件载荷或图片内容、将其复制到当前目录、处理快捷键/显式入口、冲突、权限、失败及临时资源生命周期的行为。

### Modified Capabilities

无。

## Impact

- 影响 `app/shared` 中的剪贴板模型、平台读取器、AppDrawer 操作入口以及 Desktop/Web 粘贴事件接入。
- 影响 Desktop、Android、iOS 与 Web 现有文件拖拽处理器，需要提取可被拖拽和剪贴板共同调用的数据准备逻辑。
- 影响 `core` 的外部文件导入协调、文件复制任务、冲突处理和临时资源清理集成，但不改变现有文件任务对外协议。
- 需要新增跨平台单元测试、平台适配测试及关键 UI/快捷键测试；不引入破坏性 API 变更。
