## Context

同步任务由 `SyncState` 自行扫描来源和目标，并通过 `FileState.runCopyAcrossEndpoints` 执行单项复制，因此不会经过普通复制/移动任务的 `FileOperationIgnoreResolver`。现有 Ignore 实现已经提供标准文件名、规则解析、否定语义和目录剪枝辅助，但路径偏好模式不能表达“某个同步任务独立选择规则文件”。

项目支持 Local、Device、Network 来源，Ignore 文件读取必须使用对应端点，且同步在开发阶段允许直接调整任务持久化模型而不兼容旧数据。

## Goals / Non-Goals

**Goals:**

- 让每个同步任务独立决定是否应用来源根目录中的标准 Ignore 文件。
- 让高级 Ignore、简单过滤、手动/间隔执行及目录监听使用同一排除判定。
- 在规则不可确认时停止目标写入，避免意外复制本应忽略的内容。
- 复用现有规则解析器和跨端读取能力，避免出现第二套 Ignore 语法。

**Non-Goals:**

- 不递归发现或读取子目录中的嵌套 Ignore 文件，也不允许任意规则文件路径；页面仅发现来源根目录中的标准文件名。
- 不兼容或迁移旧任务文件、旧 ProtoBuf、旧 Pro 快照和开发期缓存。
- 不改变现有 Ignore 语法，不新增规则编辑器或规则预览器。
- 不为单文件来源启用高级 Ignore；单文件仍可使用简单过滤规则。

## Decisions

### 1. 任务保存开关和标准文件名列表

`SyncTask` 增加 `useIgnoreFiles` 与 `ignoreFileNames`。开关与列表分离，使用户临时关闭时不丢失选择；执行层只在开关开启时读取列表。

列表只允许 `SupportedIgnoreFileNames`，保存时按该全局列表顺序规范化并去重。相比保存任意路径，这能阻止路径穿越并使多文件规则合并顺序稳定；相比复用路径偏好，任务配置不会受到文件浏览器当前目录状态影响。

本变更直接修改开发期持久化模型，不添加格式版本、迁移器或兼容读取分支。新任务的关闭和空列表默认值是产品默认，不构成旧格式兼容承诺。

### 2. 抽取端点感知的 Ignore 读取能力

将当前普通文件操作中的 Local、Device、Network Ignore 文件读取逻辑抽取为可复用解析器。解析器接收来源端点、来源根、路径分隔符和规范化后的文件名列表，返回 `Result<ResolvedIgnoreMatcher>`；普通文件操作可继续用数据库路径偏好构造 scope，同步则显式构造任务 scope。

严格模式要求每个选中文件读取成功并符合大小限制，随后才构建 matcher。现有宽松读取适用于普通文件列表展示的行为不扩散到同步。相比在 `SyncState` 复制远程读取代码，共享解析器能保持设备和网络读取限制一致。

### 3. 在来源快照阶段统一排除

每次运行连接来源端点并确认来源为目录后，先加载 matcher，再开始来源和目标快照。`collectSourceSnapshot` 对每个子项先执行简单规则和 `matchesOperationSkip` 的联合判定；匹配目录不加入队列，匹配文件不加入快照，选中的 Ignore 文件由 `matchesOperationSkip` 自动排除。

matcher 每次运行只加载一次，避免遍历时重复远程读取。任何加载失败在目标目录创建或文件复制前返回失败运行记录。

删除型 planner 必须接收同一 matcher 或等价的受保护路径集合，以区分“被忽略”与“来源已删除”。当前完整同步不删除目标多余项；目录监听变更落地时其校准和事件 planner 必须复用此判定。

### 4. Ignore 文件变化触发重新规划

手动和间隔任务天然在每次运行重载规则。目录监听任务需要把选中的 Ignore 文件视为控制文件：事件不能传输该文件，但必须使协调器丢弃旧 matcher、重新读取全部选中文件，并执行校准，因为规则收紧和放宽都可能改变大量路径。

如果两个变更的实现顺序不同，本变更先提供可复用过滤入口；目录监听变更在其 planner 接入该入口。二者保持独立 OpenSpec，但最终代码只保留一条过滤数据流。

### 5. 使用状态提升的 Compose 配置区并发现来源根目录候选文件

同步编辑页继续在屏幕级维护 `rememberSaveable` 表单状态。新增开关状态、文件名列表和选择弹窗状态；标题与说明所在的平面 `Row` 不添加 `toggleable` 或 `clickable`，仅由末端的 `Switch(onCheckedChange = ...)` 改变启用状态，避免点击文字或空白区域误切换。该开关行复用相邻“包含子目录”和“同步空目录”的 `fillMaxWidth`、末端开关和零额外水平内缩布局，标题使用相同的正文样式，说明作为低强调辅助文本。配置组件根节点使用平面 `Column`，不添加卡片边框或独立容器背景。

配置区放在简单过滤规则上方。页面以来源类型、端点引用和根路径组成来源身份，并以初始任务来源作为基线。来源身份变化时立即清空已确认选择、弹窗草稿和打开状态，再开始候选发现；初次进入编辑页不视为来源变化，因此不会误删任务已有选择。该清空规则与高级 Ignore 开关状态无关，切换开关本身则继续保留选择。

高级 Ignore 开启后，页面以来源身份为 `LaunchedEffect` key 异步读取根目录的直接子项，过滤目录、符号链接与非标准文件名，并按 `SupportedIgnoreFileNames` 顺序生成候选列表。路径连续变化会取消旧查询，避免旧来源结果覆盖新来源；新来源查询失败时选择保持为空且隐藏文件入口。

启用后仅当候选列表非空时显示紧凑文件入口，入口以“Ignore 文件”为主标签、已选名称或未选择状态为辅助文本，并通过末端导航图标表达可进入选择；入口使用与开关行和相邻设置相同的左右边界，不增加水平内容内缩，通过最小触控高度、垂直内边距以及与开关行之间的垂直间距避免内容拥挤，且不显示分隔边框或独立色块。没有候选时仅显示同样零水平内缩的简短状态文字，入口及图标均隐藏。弹窗使用标准 Checkbox 且只列出本次发现的候选文件。保存时再次读取来源根目录并拒绝已缺失的选中文件，以覆盖发现与保存之间的竞态；运行时仍严格读取文件内容，以覆盖保存与执行之间的变化。结构校验继续阻止“已启用但列表为空”或单文件来源配置。

## Risks / Trade-offs

- [多个 Ignore 文件之间的否定规则受合并顺序影响] → 始终按 `SupportedIgnoreFileNames` 顺序规范化和解析。
- [远程来源在保存后离线或规则文件被删除] → 每次运行严格重读，并在目标零写入阶段失败。
- [编辑页来源路径快速变化或远程目录暂时不可读] → 来源身份一变化就先清空选择，`LaunchedEffect` 再取消旧查询；失败时保持空选择并隐藏入口，保存时做权威校验。
- [忽略目录后目标删除流程误判来源缺失] → planner 显式携带 matcher/受保护路径，删除前再次应用同一排除规则。
- [16 个标准文件名占用较多页面空间] → 主页面只显示选择摘要，完整列表放入多选弹窗。
- [目录监听和本变更并行修改扫描逻辑] → 抽取共享过滤入口，并用组合测试验证最终 planner 只使用一套语义。

## Migration Plan

无需迁移。开发期旧同步任务文件和配置快照可直接清空；回滚时同样清空使用新模型生成的数据。
