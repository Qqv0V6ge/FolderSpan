## Context

参见 [proposal.md](./proposal.md) 的动机。当前客户端已经实现了账号设备 WebSocket 票据申请、协议解析、presence revision、重连状态机、连接状态 UI，以及由在线快照驱动的自动连接和自动授权；同时，既有 `DeviceState.pingDevice()` 已能发现局域网 HTTP 设备并执行永久 `AUTO_CONNECT` 策略，`RawHttpDeviceRoutes` 已集中处理入站设备连接授权。

账号设备列表已通过 `UserApiService.listDevices()` 和 `UserRepository.listDevices()` 提供，但个人资料页面的列表缓存有效期为 30 天，不具备授权所需的新鲜度。账号 API 和会话位于 `proMain`，LAN 发现、设备连接和入站路由位于 `core`，设置 UI 位于 `app/shared`，因此仍需维持 `core` 不反向依赖 `proMain` 的模块边界。

后端仓库 `/home/webb/GolandProjects/file-manager` 的提交 `3a5388cf70e1e9e4aa8306deb811126fc4a1da76` 是当前 WebSocket 接口基线。本设计只规定客户端如何消费最终的账号设备身份契约，不修改或安排该后端仓库的代码、Swagger、部署和数据迁移。

行为契约见 `specs/account-device-lan-connectivity/spec.md` 和 `specs/manage-easy-file-share-settings/spec.md`。

## Goals / Non-Goals

**Goals:**

- 将用户操作收敛为一个“自动连接我的设备”开关，不要求用户理解或配置访问密钥、设备身份密钥、角色或在线通道。
- 用账号设备归属、短期新鲜列表和端到端可验证设备身份共同决定自动连接与自动同意。
- 复用现有 LAN 扫描和直接 HTTP 设备连接，不维护账号设备长连接或服务端在线 presence。
- 对身份材料缺失、账号服务暂时不可用和缓存过期提供安全且可用的人工流程。
- 保持永久拒绝、现有手动授权、TLS 校验和角色权限边界不被账号归属绕过。

**Non-Goals:**

- 不包含后端接口删除、账号设备身份字段、签名凭据签发或服务端部署工作。
- 不自动连接仅能通过远程 WebRTC 到达的账号设备，也不为 JS/Wasm 新增局域网扫描能力。
- 不删除文件共享现有的全局访问保护功能；只是账号设备自动连接不依赖用户手动配置它。
- 不提供账号设备管理、逐设备开关、逐设备角色选择或在线状态页面。
- 不承诺在账号设备可信快照已经过期且无法刷新时离线自动授权。

## Decisions

### 1. 用短期账号设备可信快照替代 WebSocket presence

在 `core` 定义简化的会话级可信快照和注册表，快照只包含当前会话代次、获取/过期时间，以及以 `deviceKey` 为键的最小身份验证材料。`proMain` 观察“设置开启 + 有效会话”，通过一个不使用个人资料长缓存的强制刷新路径获取设备列表，再把去除 token、原始响应和无关个人信息后的快照发布给 `core`。

可信快照初始有效期设为 5 分钟。设置开启、登录成功或会话替换时立即刷新；应用恢复前台时刷新已过期或即将过期的快照；局域网扫描需要账号信任而快照过期时触发 single-flight 刷新。刷新失败时，尚在有效期内的快照可以继续使用，到期后停止产生新的账号自动信任。退出登录、关闭设置和 401/403 会话错误立即清空快照。

选择短期快照而不是继续维护增量在线事件，是因为 LAN 扫描本身已经给出了“当前可达”信号，账号服务只需要回答“是否仍属于该账号”。选择独立刷新策略而不是复用 30 天个人资料缓存，是为了限制设备删除和账号切换后的授权窗口。

### 2. 设备列表必须提供可验证身份，`deviceKey` 只用于索引

客户端账号设备 DTO 和可信项需要承载后端最终契约提供的设备身份验证材料，包括 snake_case 的 `device_key`、`identity_public_key`、`identity_algorithm` 和 `identity_key_id`。客户端 mapper 只接受这一种正式结构，并拒绝 camelCase、嵌套身份对象或缺少必要身份材料的条目进入自动信任集合。`deviceKey` 仍用于关联账号列表、LAN 设备和本地策略，但不能单独产生信任。

每台设备的身份私钥由应用自动创建和安全保存，用户不可见，也不得写入设置同步、日志或数据库快照。客户端通过一个窄的 `AccountDeviceIdentitySigner`/`AccountDeviceIdentityVerifier` 边界使用身份材料，方便公共逻辑测试和平台实现替换。

备选方案是只比较列表中的 `deviceKey`。由于该标识会随 LAN 发现消息暴露，攻击者可以复制它发送连接请求，因此不采用。另一个备选方案是把账号 access token 交给局域网对端或由对端代为校验；这会扩大账号凭据暴露面，同样不采用。

### 3. LAN 发现和连接请求使用不同用途的防重放证明

扩展客户端间 LAN 协议，增加版本化账号设备证明，并为直接连接增加必填授权模式：

```text
AccountDeviceProof
  version
  purpose              // lan-discovery 或 lan-connect
  deviceKey
  keyId
  issuedAtEpochSeconds
  nonce
  signature

DeviceConnectRequest
  authorizationMode    // STANDARD 或 ACCOUNT_DEVICE，UNSPECIFIED 拒绝
  accountDeviceProof   // ACCOUNT_DEVICE 模式必填

DeviceConnectResponse
  authorizationMode    // STANDARD 或 ACCOUNT_DEVICE，UNSPECIFIED 拒绝
```

扫描方在 ping 中提供随机 challenge，响应方对用途、协议版本、双方设备标识、challenge、返回端点/TLS 身份及响应摘要生成规范化签名。扫描方使用可信快照中的注册身份验证签名，通过后才允许账号自动连接。

连接方在设备连接请求中使用独立随机 nonce，并对 `lan-connect` 用途、双方设备标识、目标路径、时间戳和请求体摘要签名。接收方校验用途、签名、短时间窗和 nonce 防重放缓存。发现证明不能复用于连接请求，连接证明也不能在不同目标或请求体之间复用。

开发阶段不保留旧连接协议兼容：请求必须显式声明授权模式，响应必须显式声明是否由账号信任授权。`ACCOUNT_DEVICE` 模式缺少证明或验证失败时直接拒绝，不降级到普通人工授权；`STANDARD` 模式才进入现有非账号流程。发现响应没有有效证明时仍作为普通设备展示，但不会触发账号自动连接。选择签名 challenge 而不是信任自报 TLS 指纹，是因为自报值本身不能证明请求方持有已登记设备身份。

### 4. 在现有 LAN 流程中插入纯决策，不新建第二套连接栈

`DeviceState.pingDevice()` 解码并规范化发现结果后，调用纯函数式账号设备候选决策。决策输入包括开关、会话代次、快照新鲜度、设备成员资格、发现证明、是否本机、永久拒绝和当前连接状态；只有结果为 `AutoConnect` 时才调用现有 `connect(SocketDevice)`。现有设备写库、UI upsert、TLS 连接和错误状态逻辑继续复用。

按设备 ID 维护有界的 in-flight 集合，扫描重复结果、并发刷新和重复响应不得创建第二个连接任务。失败不写入永久 `AUTO_CONNECT`；后续扫描可以在前一次任务结束且退避窗口到期后重新尝试，手动连接始终可用。

选择在发现结果处决策，而不是从账号设备列表主动枚举连接，是因为列表不包含可信的实时 LAN 地址，局域网扫描才是可达性和端点信息的来源。

### 5. 入站自动授权沿用现有优先级和最小权限

`RawHttpDeviceRoutes.handleDeviceConnect` 先按必填授权模式分流。`STANDARD` 直接进入现有非账号授权流程；`ACCOUNT_DEVICE` 执行账号证明决策，优先级固定为：

1. 永久拒绝：拒绝；
2. 身份冲突、签名错误或重放：拒绝账号授权并记录脱敏原因；
3. 设置开启、会话有效、快照新鲜、成员匹配且证明有效：临时自动同意；
4. 缺少账号资格、证明或最小权限角色：拒绝本次账号授权请求，不降级。

自动同意优先复用该设备已有的有效角色；没有已保存角色时使用内置的最小权限角色，不新增角色选择设置。签发和绑定连接 token 继续走现有实现，并标记该连接是否仅依赖临时账号信任，以便设备从刷新列表移除、会话结束或开关关闭时有选择地关闭；用户已经通过其他永久策略授权的连接不受临时快照清理影响。

本变更只接入局域网直接 HTTP 请求。现有 WebRTC 授权路径移除账号 WebSocket presence 依赖后回到原有非账号决策，避免将“登录过”误解为“远程在线且可自动接入”。

### 6. 删除账号 WebSocket 客户端，但保留通用 WebSocket 能力

移除账号设备票据 API 方法和 DTO、账号 WebSocket 协议模型/客户端/协调器、presence revision 注册表、连接状态 store、应用根生命周期启动代码、依赖注入绑定、专用 UI 状态与测试。不得删除 WebRTC 信令等其他功能使用的 Ktor WebSocket 依赖或通用网络配置。

设置使用现有本机布尔键作为正式配置，只调整用户可见名称、说明和运行时含义。设置页删除“申请票据”“连接中”“在线”“退避”“设备撤销”“协议不兼容”等状态分支，只保留一个开关和必要时的普通语言登录/刷新提示。

同时删除或重写仅描述账号设备 WebSocket 的前端文档和文案，避免客户端停止调用后仍宣称存在该通道。

### 7. 会话代次和 single-flight 阻止过期异步结果生效

设备列表刷新、签名验证和自动连接任务都携带启动时的会话代次。任何异步结果写入注册表或触发连接前，必须再次确认设置仍开启、会话代次未变化且快照仍新鲜。刷新使用互斥 single-flight；旧账号的迟到响应直接丢弃。

nonce 防重放缓存按设备和用途分区，条目只保留到证明有效期结束，并设置总量上限，避免攻击流量造成无界内存增长。日志只记录设备标识的截断或哈希形式和错误类别，不记录 token、私钥、公钥完整值、签名、nonce 或完整证明。

## Risks / Trade-offs

- [REST 列表无法像 WebSocket 一样即时获知设备删除] → 使用 5 分钟短期快照、前台恢复刷新和到期 fail-closed，将撤销延迟限制在明确窗口内；刷新发现移除后关闭仅依赖临时账号信任的连接。
- [后端最终账号设备列表暂未提供可验证身份材料] → 客户端 mapper 将此类设备排除出自动信任，功能安全降级为现有人工流程；不以 `deviceKey` 匹配临时替代。
- [开发阶段客户端协议不同步] → 直接连接请求在解码或授权模式校验时失败，要求参与测试的设备升级到同一协议版本，不维护双协议分支。
- [设备时钟偏差导致新证明被拒绝] → challenge nonce 是发现证明的主要新鲜度来源，连接证明允许有限时钟偏差并结合一次性 nonce；超出窗口时本次账号自动连接失败，用户仍可通过当前协议发起标准手动连接。
- [多台设备同时扫描产生双向连接竞态] → 在现有连接状态检查之外增加按设备 in-flight 去重，连接建立或入站连接登记后取消同设备的冗余自动任务。
- [前台恢复和频繁扫描增加账号 API 压力] → 使用 5 分钟有效期、near-expiry 判断和 single-flight 合并刷新，不为每个 IP 或每个发现结果调用账号 API。
- [删除账号 WebSocket 代码误伤 WebRTC] → 删除范围按账号设备类型、DI 绑定和 API 路径定位，并保留通用 Ktor WebSocket 依赖；通过 WebRTC 既有测试验证无回归。

## Migration Plan

1. 先增加可信快照、会话代次、身份签名/验证边界和 LAN 证明模型，默认开关仍为关闭，并为缺少身份材料的响应建立 fail-closed 测试。
2. 增加独立的账号设备强制刷新路径，将结果发布到 `core`；保留个人资料页面 30 天缓存，不让它参与授权。
3. 接入 ping challenge、发现证明验证和 `DeviceState` 自动连接决策，再接入入站连接证明、最小权限自动同意和 nonce 防重放。
4. 将应用生命周期从账号 WebSocket 协调器切换到可信快照刷新协调器，随后删除票据、WebSocket presence、状态 store、协议模型和对应 DI/UI 代码。
5. 更新设置文案和前端文档，运行 `core`、`proMain`、`app/shared` 相关单元测试及 Android/JVM/JS/Wasm 编译验证。
6. 旧变更 `add-account-device-auto-connect-setting` 保持未归档并由本变更取代；完成实现后只归档反映 LAN 方案的规范，避免把已废弃的 WebSocket 行为写入主规范。

回滚时可关闭或移除新的 LAN 账号决策入口，现有手动扫描、手动连接、手动批准和永久设备策略仍可独立工作。账号设备 WebSocket 客户端不会作为回滚路径重新启用。
